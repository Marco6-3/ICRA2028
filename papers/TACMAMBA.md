# TacMamba 阅读笔记

来源：[arXiv 2603.01700v1](https://arxiv.org/html/2603.01700v1)。核验：2026-10-05。已读 §IV 方法、§V 设置与比较；未审计代码、未复现。

## 核心角色

论文让触觉编码器持续更新隐状态，再把压缩历史作为 soft prompt 注入较低频的 VLA。文中设置为 100 Hz 触觉流与约 1 Hz 规划；这是历史处理速率与规划速率，不能直接改写为 100 Hz 动作修正策略。

作者还提出时序关系自监督与阶段均匀采样。收益可能同时来自输入历史、学习目标、采样和架构，因此只比较整体系统不能隔离 Mamba selectivity 的作用。

## Selectivity 应如何理解

Mamba 的部分状态空间参数依赖当前输入，允许状态更新随事件变化。这为抑制噪声、保留重要接触事件提供了候选机制，但“像自适应物理滤波器”是一种解释，不能仅凭网络公式宣布它辨识了真实接触动力学。

固定大小状态的逐步更新，对历史长度可以具有常数级单步开销；这不代表无损记忆、固定硬件上的硬实时保证，也不代表任何 Transformer 都无法实时运行。

## 对实验结论保持精确

§V 使用 Piper 与单轴力传感器。作者报告编码器准确率/时延比较，以及视觉歧义下的真实任务。闭环比较主要针对视觉策略；离线编码器比较不能替代同设置闭环 GRU/Transformer 比较。

特别注意：文中同列单向 LSTM 和双向 LSTM；递归模型可以缓存状态，不能以每步重算长历史的实现，论证所有 RNN 都不适合流式控制。本项目应加入持续状态 GRU、固定窗口注意力和简单事件记忆，并测完整链路。

## 对本路线的启发

把 TacMamba 视为“让历史可被策略使用”的起点，进一步检验记忆是否能改善执行时修正，以及该记忆应如何随接触切换保留/遗忘。

若 GRU 同样有效，应承认主要收益来自历史信息，而非 Mamba；若只有事件计数改善，则主张应限于任务状态记忆，不能推广到连续接触控制。
