# TacForcing 阅读笔记与理解修正

来源：[arXiv 2608.25798](https://arxiv.org/html/2608.25798)。核验：2026-10-05。已读 §3 方法、§4 实验及 EATA 消融；未审计代码、未复现。

## 核心方法

TacForcing 将动作 chunk 分成顺序执行的 blocks。临近动作先完成生成并执行，后续块保留中间状态；新的触觉反馈在执行过程中进入生成器。

Execution-Aware Tactile Attention（EATA）限制**当前触觉对下一待执行块的直接注意力访问**，避免用当前接触状态直接条件化更远的动作。

## 两个需要纠正的理解

1. **“后续动作块不更新”不准确。** §3 说明全部未完成块按各自 flow schedule 继续演化；EATA 限制的是它们对当前触觉 token 的直接访问，不是停止它们的去噪。
2. **“EATA 没有实验支持”不准确。** §4.3 比较无触觉、初始固定触觉、执行时刷新但无 EATA、完整方法。作者报告加入 EATA 后，消融任务子集的仿真均值由 51% 到 60%，真机均值由 48% 到 69%。

这些消融支持文中设置下的设计有效，并不证明所有历史方案、block 大小和注意力范围都不可能更好。也不能把消融子集均值与全部任务均值混为一谈。

## 与历史触觉研究的关系

EATA 回答“本次触觉直接作用于哪些待执行动作”；历史编码回答“本次提供给动作生成器的触觉表示含什么信息”。这两个轴可以分开研究。

拟检验的扩展：保持执行对齐机制和刷新时刻不变，比较当前表示、固定历史窗、指数衰减历史、流式选择性状态。前提是先核验所用触觉编码器是否已经含时间信息，避免把“当前 token”误认为“完全没有历史”。

指数衰减可作为简单强基线，但会压低早期关键事件，不能预先断言优于当前输入。需要同时测连续接触、状态切换与长间隔事件，并避免因增加更多历史 token 改变计算预算。
